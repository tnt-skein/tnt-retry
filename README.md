# tnt-retry

Повторы неудавшихся действий для Tarantool: пауза растёт степенью
и размазана случаем, классификатор отличает временный отказ
от постоянного, общий срок держит предел времени, а бюджет повторов
и размыкатель не дают клиенту добивать лежащую службу.

```lua
local retry = require('tnt.retry')

-- Разовый вызов: до трёх попыток, паузы до 0,1 и до 0,2 с.
local value, err = retry.run(function()
    return client:get(key)
end)

-- Политика: настройки проверены один раз, при сборке.
local call = retry.policy({
    attempts = 6,
    deadline = 10,                                     -- весь вызов — не дольше десяти секунд
    scope = 'склад',                                   -- своё ведро бюджета у этой службы
    breaker = retry.breaker.new({ name = 'склад' }),   -- лежащую службу не зовём вовсе
})

local rows, failure = call(function(context)
    return conn:call('stock', { 'яблоки' }, { timeout = context.left })   -- остаток срока
end)
```

Отказ — пара `nil, err` с причиной последней попытки.

Зависимости: `tnt-must` (текст отказа о незнакомой настройке),
`tnt-clock` (монотонные часы, время планировщика и пауза), `tnt-log`
(журнал) и `tnt-external` (подмена часов, паузы и случая в проверках).

## Зачем

Цикл «попытка, пауза, ещё попытка» пишет каждый сетевой клиент, и каждый
ошибается в нём по-своему: забывает разброс и добивает вставший сервер,
повторяет «неверный пароль», делает шесть попыток по пять секунд там, где
вызывающий готов ждать десять, спрашивает лежащую службу снова и снова.
Пакет делает семь вещей:

- **Отступ растёт степенью и размазан случаем** — `jitter` от 0 до 1
  либо `'decorrelated'`; случай — из байтов ядра, свой у каждого процесса.
- **Классификатор решает, что повторять**: поле `retriable` в отказе,
  код ответа, слова отказа. Неизвестное повторяется,
  `retry.classify.strict` — нет.
- **Срок на весь вызов** — `deadline`; остаток отдаётся действию
  в `context.left` и `context.remaining()`.
- **Просьба сервера подождать** (`retry_after`) удлиняет паузу, а просьба
  дольше потолка отменяет повтор.
- **Бюджет повторов** — ведро жетонов на получателя: когда отказов много,
  повторы срезаются сами.
- **Размыкатель** — после череды отказов служба не зовётся вовсе, раз
  в срок идёт проба.
- **Опечатка в настройке — отказ**, а не молчаливое умолчание:
  `attemps = 10` не даёт ни одной попытки и называет знакомые ключи.
  Так же проверяются настройки ведра и размыкателя.

## Установка

```sh
tt rocks install tnt-retry --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-retry.git
cd tnt-retry && tt rocks make
```

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `retry.run(action, opts)` | выполняет действие с повторами; отказ — `nil, err` |
| `retry.policy(opts)` | собирает функцию повтора `call(action, extra)`; негодные настройки — `nil, err` |
| `retry.configure(opts)` | настраивает общий экземпляр; `true` либо `false, err` |
| `retry.new(opts)` | отдельный экземпляр со своими вёдрами |
| `retry.reset()` | наливает вёдра бюджета заново |
| `retry.status()` | настройки, худшее время в паузах, вёдра, размыкатель |
| `retry.breaker.new(opts)` | размыкатель: `call`, `allow`, `record`, `state`, `status`, `reset` |
| `retry.classify` | `verdict`, `of`, `strict`, открытые списки слов |

Настройки: `attempts` (3), `base` (0,1), `factor` (2), `jitter` (1),
`max` (5), `deadline`, `retriable`, `on_attempt`, `scope` (`'default'`),
`breaker`, а экземпляру ещё `budget` (`{ tokens = 100, ratio = 0.1 }`
либо `false`).

```lua
retry.run(action, { attemps = 10 })
--> nil, 'настройки повторов: ключа «attemps» нет, есть attempts, base, breaker, deadline, factor, jitter, max, on_attempt, retriable, scope'
retry.new({ budget = { token = 4 } })
--> nil, 'настройки повторов: настройка budget: ключа «token» нет, есть ratio, tokens'
retry.breaker.new({ treshold = 0.1 })
--> app.lua:1: настройки размыкателя: ключа «treshold» нет, есть min_calls, name, probes, reset_timeout, retriable, threshold, window
```

Каждый отказ настроек повторов начинается словами «настройки повторов»,
кто бы ни передал настройки, и своей приставки тот, кто передаёт отказ
дальше, не ставит. Размыкатель на негодных настройках бросает: его
заводят прямо в настройках повторов, и `nil` из пары молча стал бы там
«без размыкателя».

`on_attempt(info)` слышит каждую попытку — номер, исход, причину, паузу —
и то, почему повторы кончились: `permanent`, `attempts`, `deadline`,
`budget`, `asked`, `breaker`.

Пакет не знает, можно ли повторять само действие: перевод денег,
оборвавшийся после приёма, повторится вторым переводом.
Неидемпотентное действие повторяют только под ключом `tnt-once`.

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (159 проверок,
545 мутантов в девяти модулях). Паузы, сроки и размыкатель проверяются
на часах, которые двигает сама проверка, и на случае, выбранном
проверкой: минутное ожидание не занимает минуту.
