# Повторы

`tnt-retry` повторяет неудавшееся действие, пока в этом есть смысл:
пауза между попытками растёт степенью и размазана случаем, классификатор
отличает временный отказ от постоянного, общий срок держит предел
времени, а бюджет повторов и размыкатель не дают клиенту добивать
лежащую службу.

```lua
local retry = require('tnt.retry')

local value, err = retry.run(function() return client:get(key) end)   -- до трёх попыток, паузы до 0,1 и до 0,2 с
```

Отказ — пара `nil, err` с причиной последней попытки. Сколько было
попыток и почему они кончились, рассказывают `on_attempt` и журнал.

Зависимости: `tnt-must` (текст отказа о незнакомой настройке),
`tnt-clock` (монотонные часы, время планировщика и пауза), `tnt-log`
(журнал) и `tnt-external` (подмена часов, паузы и случая в проверках).
Остальное встроено в Tarantool — `digest` для случая.

## Зачем пакет

Цикл «попытка, пауза, ещё попытка» пишет каждый сетевой клиент.
Написанный заново, он в каждом клиенте ошибается по-своему, и все ошибки
выглядят безобидно, пока не придёт авария:

- **пауза без разброса** — тысяча клиентов, отказавших в одну секунду,
  повторяет в одну и ту же, и вставший сервер получает тысячу запросов
  одним ударом и ложится снова;
- **повторяется всё подряд** — «неверный пароль» десять раз за минуту,
  десять одинаковых отказов и десять записей о неудачном входе в чужом
  журнале безопасности;
- **число попыток без срока** — шесть попыток по пять секунд там, где
  вызывающий готов ждать десять;
- **повторы множатся** — три попытки на каждом из четырёх уровней дают
  восемьдесят один запрос на один исходный, и множитель включается ровно
  тогда, когда сервер и так не справляется;
- **лежащую службу спрашивают снова и снова** — каждый вызов честно
  проходит все попытки и все паузы, хотя после первого десятка отказов
  всё уже ясно;
- **отказ без причины** — `return nil` и брошенная ошибка доходят
  до вызывающего как «не вышло», а почему — не сказано.

Пакет делает для этого семь вещей:

- **Отступ растёт степенью и размазан случаем.** `jitter` — доля паузы,
  отданная случаю, от 0 до 1, либо `'decorrelated'`. Случай берётся
  из байтов ядра, и у каждого процесса он свой.
- **Классификатор решает, что повторять**: поле `retriable` в отказе,
  код ответа, слова отказа. Неизвестное повторяется; строгий вариант
  повторяет только известное временное.
- **Срок на весь вызов.** `deadline` не даёт начать попытку, которой
  не хватит времени, а остаток срока отдаётся действию для его таймаута.
- **Просьба сервера подождать соблюдается**: `retry_after` в отказе
  удлиняет паузу, а просьба дольше потолка отменяет повтор.
- **Бюджет повторов** — ведро жетонов на каждого получателя: когда
  отказов много, повторы срезаются сами, без выключателя и без человека.
- **Размыкатель** после череды отказов перестаёт звать службу вовсе
  и раз в срок пропускает пробу.
- **Настройки повторов проверяются сразу** — и вложенные настройки ведра,
  и настройки размыкателя. Опечатка в имени и негодное значение — отказ
  при сборке политики, а не молчаливое умолчание в аварии.

## Как пользоваться

### Разовый вызов: `run`

```lua
local retry = require('tnt.retry')

local tries = 0

local value, err = retry.run(function()
    tries = tries + 1

    if tries < 3 then
        return nil, 'connection refused'   -- временный отказ: будет повтор
    end

    return 'готово'
end)

value   --> 'готово'
err     --> nil
tries   --> 3: паузы между попытками — до 0,1 и до 0,2 с
```

Действие — функция, которая отвечает парой: значение при удаче,
`nil` или `false` с причиной при отказе. Брошенная ошибка — тоже отказ,
и её текст — причина: сетевые библиотеки бросают охотно, а клиент,
роняющий вызов чужой ошибкой, не годится ни на что.

`run` отвечает тем, что вернула удачная попытка, — значением и вторым
значением, — либо `nil` и причиной последнего отказа. Причина — та, что
назвало действие, а не сводка: вызывающему нужно знать, чем именно
кончилось.

```lua
local value, err = retry.run(function()
    return nil, 'неверный пароль'
end)

value   --> nil
err     --> 'неверный пароль': отказ постоянный, попытка была одна
```

Отказ без причины получает её здесь, и вызывающий, журнал и размыкатель
видят одно и то же:

```lua
retry.run(function()
    return nil
end, { attempts = 1 })
--> nil, 'действие отказало и причины не назвало'
```

Единственный аргумент действия — `context`:

| Поле | Что это |
|---|---|
| `attempt` | номер попытки, с единицы |
| `elapsed` | сколько секунд прошло от начала вызова |
| `left` | остаток срока на начало попытки; `nil`, если срока нет |
| `remaining()` | остаток срока прямо сейчас; `nil`, если срока нет |

Не функция вместо действия — отказ парой, а не бросок:

```lua
retry.run('сходи к серверу')
--> nil, 'повторять нечего: действие должно быть функцией, а пришло: string'
```

### Настройки

| Настройка | Умолчание | Что значит |
|---|---|---|
| `attempts` | `3` | сколько попыток всего, считая первую; `math.huge` — только вместе со сроком |
| `base` | `0.1` | первая пауза в секундах |
| `factor` | `2` | во сколько раз растёт пауза; не меньше 1 |
| `jitter` | `1` | доля паузы, отданная случаю, от 0 до 1, либо `'decorrelated'` |
| `max` | `5` | потолок одной паузы в секундах; не меньше `base` |
| `deadline` | нет | срок на весь вызов в секундах, больше нуля |
| `retriable` | `retry.classify.of` | что повторять: функция от причины отказа |
| `on_attempt` | нет | что звать после каждой попытки |
| `scope` | `'default'` | имя ведра бюджета — обычно имя получателя |
| `breaker` | нет | размыкатель из `retry.breaker.new` |
| `budget` | `{ tokens = 100, ratio = 0.1 }` | ведро бюджета; только экземпляру; `false` — без бюджета |

Настройки вызова ложатся поверх настроек экземпляра, и проверяется
то, что вышло из слияния, — с ним и пойдут попытки. Проверяется всё
и сразу, до первой попытки, и отказ — пара `nil, err`:

```lua
retry.run(action, { attemps = 10 })
--> nil, 'настройки повторов: ключа «attemps» нет, есть attempts, base, breaker, deadline, factor, jitter, max, on_attempt, retriable, scope'

retry.run(action, { factor = 0.5 })
--> nil, 'настройки повторов: настройка factor не может быть меньше 1'

retry.run(action, { attempts = math.huge })
--> nil, 'настройки повторов: бесконечные повторы без срока: задайте deadline или конечный attempts'

retry.run(action, { base = 1, max = 0.5 })
--> nil, 'настройки повторов: настройка max меньше base: потолок ниже первой же паузы'
```

Каждый отказ начинается словами «настройки повторов»: пакет называет
себя сам, и текст один, кто бы ни передал настройки, — прикладной код,
клиент HTTP или драйвер. Тот, кто передаёт отказ дальше, своей приставки
не ставит: иначе вызывающий прочёл бы её дважды подряд.

Опечатка в имени — отказ, а не безобидная добавка: `attemps = 10`
иначе не применилось бы, и повторов было бы три вместо десяти, о чём
не сказал бы никто. `factor = 0.5` уменьшал бы паузу с каждой попыткой
и превращал защиту в ускоритель лавины. Настройка повторов задаётся
однажды и живёт годами, а её ошибка проявляется только в аварии —
поэтому её ловят при сборке, а не в тот день, когда она сработает.

Остальные отказы настроек — после тех же слов «настройки повторов: »:

```text
настройка attempts — целое число от 1, а пришло: 1.5
настройка base должна быть числом, а пришло: nan
настройка base не может быть меньше 0
настройка jitter — доля от 0 до 1 либо 'decorrelated', а пришло: 3
настройка deadline — срок в секундах больше нуля, а пришло: 0
настройка retriable должна быть функцией
настройка on_attempt должна быть функцией
настройка breaker — размыкатель из retry.breaker.new
настройка budget — таблица настроек ведра либо false
настройка budget: ключа «token» нет, есть ratio, tokens
настройка budget.tokens — конечное число больше нуля, а пришло: inf
настройка budget.ratio — доля больше 0 и не больше 1, а пришло: 0
настройка scope — имя ведра строкой, а пришло: 5
```

Настройки не таблицей — тот же отказ парой, и он тоже называет себя:
`'настройки повторов — таблица, а не строка'`.

Границы записаны сравнением «годится», а не «не годится»: сравнение
с NaN всегда ложно, и так он не проходит ни одну из них. Разброс или
срок длиной NaN, пропущенные границей с отрицанием, сломали бы паузу
посреди аварии.

### Отступ и разброс: `base`, `factor`, `max`, `jitter`

Пауза перед повтором считается от номера сделанной попытки `n`:

```text
raw   = min(base * factor^(n - 1), max)
пауза = raw * (1 - jitter) + random() * raw * jitter
```

Отступ растёт не из вежливости: повторы — добавленная нагрузка ровно
в тот миг, когда её и так больше, чем сервер держит, и редеющие попытки
дают ему разгрестись. Разброс важнее самой степени: без него тысяча
клиентов, отказавших в одну секунду, повторит в одну же.

```lua
local backoff = retry.backoff
local opts = { base = 0.1, factor = 2, max = 5 }

backoff.raw(1, opts)   --> 0.1
backoff.raw(4, opts)   --> 0.8
backoff.raw(7, opts)   --> 5: 6,4 срезано потолком
```

`jitter` — ручка с непрерывной шкалой, а не выбор из списка названий:

- `0` — разброса нет, чистая степень: 0,1, 0,2, 0,4…;
- `0.5` — «равный разброс» (equal jitter): половина паузы гарантирована,
  половина случайна; годится тому, кому нужна нижняя граница паузы;
- `1` — «полный разброс» (full jitter), умолчание: пауза равномерна
  от нуля до расчётной. Так меньше всего лишних обращений, когда
  клиентов много.

`'decorrelated'` считает паузу не от номера попытки, а от прошлой паузы:
`min(max, random(base, прошлая * 3))`. Она растёт в среднем в полтора
раза за попытку и не имеет «ступеней», к которым могут сойтись клиенты,
но помнит прошлую паузу — и потому живёт только внутри одного вызова.

```lua
local slow = retry.policy({ jitter = 'decorrelated', base = 0.1, max = 5 })
```

Случай берётся у ядра — `digest.urandom`, четыре байта на паузу, —
а не у `math.random`: его Tarantool не сеет, и каждый процесс начинает
с одной и той же последовательности. Узлы, отказавшие в один миг,
получили бы одни и те же паузы.

Сколько вызов может простоять в паузах, показывает `worst_case`
в `status()`: разброс паузу только укорачивает, поэтому это верхняя
граница. Для `'decorrelated'` это оценка по степени.

```lua
local own = retry.new({ attempts = 4, base = 0.2, factor = 3, max = 9 })

own:status().worst_case   --> 2.6: 0,2 + 0,6 + 1,8 — три паузы на четыре попытки
```

### Срок: `deadline`

Шесть попыток по пять секунд — полминуты ожидания там, где вызывающий
готов ждать десять секунд. `deadline` — срок на весь вызов, от его
начала. Он не обрывает идущую попытку — оборвать чужой вызов на середине
отсюда нельзя, у него свои сроки, — а решает, начинать ли следующую:
если пауза перед ней уже упирается в срок, повторов больше нет.

```lua
local seen = {}

retry.run(function(context)
    table.insert(seen, context.attempt)

    return nil, 'timeout'
end, { attempts = 10, base = 0.02, jitter = 0, deadline = 0.1 })

seen   --> { 1, 2, 3 }: паузы 0,02 и 0,04; следующая, 0,08, вышла бы за срок
```

Остаток срока действие получает в `context.left` и складывает в свой
таймаут — тогда и сама попытка кончается в срок вызова:

```lua
local call = retry.policy({ deadline = 2, scope = 'склад' })

local rows, err = call(function(context)
    return conn:call('stock', { 'яблоки' }, { timeout = context.left })
end)
```

`context.left` — снимок на начало попытки, и годится он одному ожиданию,
начатому сразу. Действие, которое ждёт не один раз — соединение, потом
ответ, — или уступает управление перед ожиданием, спрашивает
`context.remaining()` перед каждым: снимок, отданный второму ожиданию,
продлил бы попытку за срок вызова на всё время первого.

```lua
local rows, err = call(function(context)
    local ready = conn:wait_connected(context.remaining())

    if not ready then
        return nil, 'соединение закрыто'
    end

    return conn:call('stock', { 'яблоки' }, { timeout = context.remaining() })
end)
```

Остаток считается от времени планировщика (`tnt-clock`,
`scheduler_now`), а не от настоящих часов: таймаут ожидания Tarantool
отсчитывает от отметки цикла событий, а она стоит, пока идёт работа
без уступки. Остаток по настоящим часам после такой работы кончился бы
раньше срока. По той же причине к паузе перед повтором прибавляется
отставание отметки: пауза, названная сервером, не укорачивается.
Прошедшее время `elapsed` и само решение о сроке — по настоящим
монотонным часам.

`attempts = math.huge` разрешён только со сроком: бесконечные повторы
без срока — вызов, который не кончается никогда.

```lua
local patient = retry.policy({ attempts = math.huge, deadline = 30 })
```

### Что повторяется: `retriable` и `retry.classify`

Повтор помогает в одном случае: когда в следующий раз выйдет то, что
не вышло сейчас. «Перегружен» через секунду сменится другим ответом,
«неверный пароль» останется тем же и через час. Приговор отказу
выносится по трём уликам, в таком порядке:

1. **Слово отказа** — поле `retriable` со значением `true` или `false`.
   Тот, кто разбирает протокол, знает о своём отказе больше всех.
2. **Код ответа** — из полей `status`, `status_code` или `http_status`.
   408, 425 и 429 повторяются, 501 и 505 — нет, прочие 5xx повторяются,
   всё остальное — нет.
3. **Слова в тексте отказа.** Сначала смотрятся слова постоянных
   отказов, потом временных.

Нет улик — приговор «неизвестно», и умолчание `classify.of` такой отказ
повторяет.

```lua
local classify = retry.classify

classify.verdict({ status = 503 })                     --> 'transient'
classify.verdict({ status = 429 })                     --> 'transient'
classify.verdict({ status = 404 })                     --> 'permanent'
classify.verdict({ retriable = true, status = 404 })   --> 'transient': слово главнее кода
classify.verdict('Неверный пароль')                    --> 'permanent'
classify.verdict('connection refused')                 --> 'transient'
classify.verdict('что-то пошло не так')                --> 'unknown'

classify.of('что-то пошло не так')                     --> true: умолчание повторяет неизвестное
classify.strict('что-то пошло не так')                 --> false: только известное временное
```

Отказ читается любым: строкой, таблицей с полем `message` или `err`,
объектом `box.error` — у него поля полезной нагрузки тоже улики — или
чем угодно с `__tostring`. Регистр не важен, и для кириллицы тоже.
Чтение полей идёт под `pcall`: чужая метатаблица вправе бросить,
а классификатор, роняющий вызов при разборе отказа, превращает беду
сервера в беду узла.

```lua
classify.verdict(box.error.new({ type = 'RemoteError', reason = 'занято', retriable = false }))
--> 'permanent'
classify.verdict({ message = 'Connection reset by peer' })
--> 'transient'
```

Код берётся только из полей и никогда из текста. В HTTP 5xx — беда
сервера, а 4xx — вина запроса; в SMTP ровно наоборот. Три цифры в начале
строки не говорят, чей это протокол, и угадавший неверно повторяет то,
что повторять нельзя. Поле `code` не берётся тоже: у ошибок Tarantool
это собственный номер ошибки, и 77 там значит не «77 по HTTP».

Слова постоянных отказов — учётные данные и права («неверный пароль»,
«access denied», «forbidden», «unauthorized»…), негодный запрос («bad
request», «invalid argument», «not implemented») и ошибки самого Lua
(«attempt to index», «attempt to call»…): повтор выполнит ту же строку
с тем же результатом. Слова временных — сеть («connection refused»,
«connection reset», «broken pipe», «no route to host», «сеть пропала»…),
сроки («timeout», «timed out», «время ожидания»), занятость
(«перегружен», «try again», «temporarily») и смена лидера («read-only
instance», «is loading», «quorum»). Полные списки — массивы
`classify.permanent` и `classify.transient`, и они открыты: пакет,
знающий свои отказы, дописывает в них свои слова.

```lua
table.insert(retry.classify.transient, 'реплика догоняет')

classify.verdict('реплика догоняет лидера')   --> 'transient'
```

Своё суждение — настройкой `retriable`:

```lua
local call = retry.policy({
    retriable = function(err)
        return type(err) == 'table' and err.conflict == true
    end,
})
```

`retriable` зовётся под `pcall`. Бросивший считается сказавшим
«не повторять»: повторять, опираясь на сломанное суждение, значит бить
по серверу наугад. Бросок записывается в журнал.

`classify.code_of(err)` и `classify.delay_of(err)` отдают код ответа
и просьбу подождать, если отказ их принёс.

### Сервер просит подождать: `retry_after`

Отказ с полем `retry_after` — число секунд, можно строкой — удлиняет
паузу до названной: сервер один знает, когда у него снова будет место.
Короче расчётной паузу просьба не делает.

```lua
local delays = {}

retry.run(function(context)
    if context.attempt == 1 then
        return nil, { status = 503, retry_after = 0.05 }
    end

    return 'готово'
end, {
    base = 0.01,
    jitter = 0,
    on_attempt = function(info)
        table.insert(delays, info.delay)
    end,
})

delays   --> { 0.05 }: расчётная пауза была 0,01
```

Просьба дольше потолка `max` отменяет повтор совсем: прийти раньше —
сделать ровно то, о чём просили не делать, а ждать дольше потолка
вызывающий не подписывался. Просьба ровно в потолок соблюдается.

```lua
local _, err = retry.run(function()
    return nil, { status = 429, retry_after = 30 }
end, { max = 5 })

err   --> тот самый отказ { status = 429, retry_after = 30 }, попытка одна
```

Дата вместо числа секунд не разбирается: она меряется часами сервера,
а они расходятся с нашими.

### Отчёт о попытках: `on_attempt`

`on_attempt(info)` зовётся после каждой попытки:

| Поле | Когда есть | Что это |
|---|---|---|
| `attempt` | всегда | номер попытки |
| `ok` | всегда | удалась ли |
| `elapsed` | всегда | сколько секунд прошло от начала вызова |
| `err` | при отказе | причина |
| `delay` | будет повтор | пауза перед ним |
| `reason` | повторов больше нет | почему |

Причин остановиться шесть, и каждая названа: по молчаливой остановке
не отличить сервер, отказавший навсегда, от бюджета, кончившегося
на здоровом сервере.

| `reason` | Постоянная | Почему повторов нет |
|---|---|---|
| `'permanent'` | `retry.runner.PERMANENT` | отказ не из тех, что лечит время |
| `'attempts'` | `retry.runner.ATTEMPTS` | попытки кончились |
| `'deadline'` | `retry.runner.DEADLINE` | срок не оставил места ещё одной попытке |
| `'budget'` | `retry.runner.BUDGET` | бюджет повторов исчерпан |
| `'asked'` | `retry.runner.ASKED` | сервер просит ждать дольше `max` |
| `'breaker'` | `retry.runner.BREAKER` | размыкатель не пустил попытку |

```lua
local heard = {}

retry.run(function()
    return nil, 'timeout'
end, {
    attempts = 2,
    base = 0.01,
    jitter = 0,
    on_attempt = function(info)
        table.insert(heard, info)
    end,
})

heard[1]   --> { attempt = 1, ok = false, err = 'timeout', elapsed = 0…, delay = 0.01 }
heard[2]   --> { attempt = 2, ok = false, err = 'timeout', elapsed = 0.01…, reason = 'attempts' }
```

Значения удачной попытки `on_attempt` не получает: обработчик почти
всегда пишет в журнал или в метрики, а значение — те самые данные,
ради которых вызов делался. `on_attempt` зовётся под `pcall`; бросок
записывается в журнал и повторов не ломает.

### Политика: `policy`

Настройки, которые повторяются в каждом вызове, собираются один раз:

```lua
local call, err = retry.policy({ attempts = 6, deadline = 10, scope = 'склад' })

local value, failure = call(action)
local value, failure = call(action, { attempts = 2 })   -- поверх настроек политики
```

Настройки проверяются при сборке: политика, собранная при старте, либо
годится, либо отказывает сразу — а не посреди аварии, ради которой её
и заводили.

```lua
retry.policy({ factor = 0.5 })
--> nil, 'настройки повторов: настройка factor не может быть меньше 1'
```

Настройки отдельного вызова проверяются при вызове, и отказ — тоже пара.

### Бюджет повторов: `budget` и `scope`

Предел попыток в одном вызове не спасает от лавины: три попытки вместо
одной — утроенная нагрузка, а если между клиентом и сервером есть
посредник, который тоже повторяет, множители перемножаются. Бюджет —
ведро жетонов. Каждая неудачная попытка забирает жетон, каждая удачная
возвращает `ratio` жетона. Повторять разрешено, пока жетонов больше
половины ведра.

Смысл в соотношении, а не в числе: при `ratio = 0.1` повторы живут, пока
отказывает меньше каждого десятого вызова, и кончаются, когда служба
лежит по-настоящему. Здоровая система жетоны не тратит, больная
перестаёт добивать себя сама.

Бюджет включён по умолчанию: ведро на сто жетонов, и полсотни неудачных
попыток подряд срезают повторы, пока удачные вызовы не нальют его
обратно. Первую попытку бюджет не трогает никогда — он ограничивает
лишнюю работу, а не работу вообще.

Ведро своё у каждого `scope`: общее ведро на процесс означало бы, что
лежащая служба отбирает повторы у здорового соседа. Вёдра заводятся
по первому обращению.

```lua
local own = retry.new({ attempts = 10, base = 0.01, jitter = 0, budget = { tokens = 4 } })
local tries = 0

own:run(function()
    tries = tries + 1

    return nil, 'timeout'
end, { scope = 'склад' })

tries                       --> 2: два отказа сняли половину ведра на четыре жетона
own:status().budget.склад   --> { tokens = 2, max = 4, ratio = 0.1, allowed = false }

own:reset()                 -- ведро снова полное: беду починили руками
```

`budget` задаётся только экземпляру: ведро общее для всех его вызовов,
и отдельный вызов со своим ведром обходил бы защиту. У вызова это
незнакомый ключ. `budget = false` выключает бюджет.

```lua
local unlimited = retry.new({ budget = false })
```

Настройки ведра проверяются вместе с остальными, при сборке экземпляра,
и отказ — та же пара: ведро заводится по первому обращению, посреди
работы, и узнать о негодной настройке оттуда было бы слишком поздно.
Незнакомый ключ — отказ, а не умолчание: `{ token = 4 }` иначе дал бы
ведро на сто жетонов.

```lua
retry.new({ budget = { token = 4 } })
--> nil, 'настройки повторов: настройка budget: ключа «token» нет, есть ratio, tokens'
retry.new({ budget = { tokens = math.huge } })
--> nil, 'настройки повторов: настройка budget.tokens — конечное число больше нуля, а пришло: inf'
```

`tokens` — конечное число больше нуля: повтор разрешён, пока жетонов
больше половины, а половина бесконечности — та же бесконечность, и ведро
без дна не пустило бы ни одного повтора. Без бюджета — это
`budget = false`. `ratio` — доля больше 0 и не больше 1: удача,
не возвращающая ничего, опустошила бы ведро навсегда.

`retry.budget.new(opts)` заводит ведро и сам, для своих циклов,
а негодные настройки бросает — с местом того, кто его заводит.
`retry.budget.complaint(opts)` отдаёт текст отказа без броска либо `nil`.

`reset()` наливает вёдра заново — нужно, когда беду починили руками:
ведро наливается удачными вызовами, а их неоткуда взять, пока повторы
срезаны.

### Размыкатель: `retry.breaker`

Повторы лечат отказ одного вызова, но не лежащую службу: пока она лежит,
каждый вызов проходит весь свой набор попыток, честно ждёт между ними
и честно отказывает. Размыкатель перестаёт звать туда, где не берут
трубку.

```lua
local breaker = retry.breaker.new({ name = 'склад', min_calls = 2, window = 4 })

local call = retry.policy({ attempts = 1, breaker = breaker })

call(function() return nil, 'connection refused' end)
call(function() return nil, 'connection refused' end)

breaker:state()   --> 'open': два отказа из двух
call(function() return 'готово' end)
--> nil, 'размыкатель разомкнут: склад не отвечает, проба через 30.0 с'
```

Три состояния:

- **замкнут** (`'closed'`) — вызовы идут, исходы считаются в окне
  последних `window`;
- **разомкнут** (`'open'`) — вызовы не идут вовсе, отказ мгновенный;
- **полуоткрыт** (`'half_open'`) — через `reset_timeout` пропускается
  `probes` вызовов; первая удачная проба замыкает цепь, первая неудачная
  размыкает снова, а лишние вызовы на пробе получают отказ
  «размыкатель на пробе: склад ещё проверяется».

```lua
local quick = retry.breaker.new({ name = 'склад', min_calls = 1, reset_timeout = 0.05 })

quick:call(function() return nil, 'connection refused' end)
quick:state()                     --> 'open'
fiber.sleep(0.06)
quick:state()                     --> 'half_open': пора пробовать
quick:call(function() return 'готово' end)
quick:state()                     --> 'closed'
```

Полуоткрытое состояние — главное в устройстве: без него размыкатель
либо не замыкается никогда, либо пускает поток целиком и снова кладёт
едва вставшую службу. Переход в него делается при обращении, а не
по таймеру: размыкатель, которого никто не зовёт, ничего и не делает.

Считаются не все отказы, а только те, что говорят о сервере: исход
здоровый, если вызов удался **или** отказ не из тех, что повторяют.
«Неверный пароль» — здоровый ответ здорового сервера, и размыкать цепь
от чужой опечатки в пароле значит уронить работу всех остальных.
Судит тот же `retriable`, что и у повторов, — по умолчанию
`classify.of`.

| Настройка | Умолчание | Что значит |
|---|---|---|
| `name` | `'служба'` | кого зовём; попадает в текст отказа и в журнал |
| `threshold` | `0.5` | доля отказов в окне, после которой цепь размыкается |
| `window` | `20` | сколько последних исходов помнить |
| `min_calls` | `10` | сколько исходов нужно для первого решения |
| `reset_timeout` | `30` | сколько секунд молчать перед пробой |
| `probes` | `1` | сколько вызовов пускать на пробе |
| `retriable` | `retry.classify.of` | что считать бедой сервера |

Окно — по числу вызовов, а не по времени: у редко зовущего клиента окно
по времени почти всегда пусто, и решение принималось бы по одному-двум
исходам, то есть по шуму. `min_calls` не даёт решать по двум отказам
из двух на здоровом потоке.

`threshold` — доля больше 0 и не больше 1: порог больше единицы
не достигается никогда. `window`, `min_calls` и `probes` — целые от 1,
`reset_timeout` — секунды больше нуля, `name` — строка, `retriable` —
функция. `min_calls` не больше `window`: окно помнит ровно `window`
исходов, и цепь, которой для решения нужно больше, не разомкнётся
никогда, как бы служба ни лежала.

Незнакомый ключ и негодное значение — бросок с местом того, кто заводит
размыкатель, а не пара `nil, err`. Размыкатель заводят прямо
в настройках повторов (`breaker = retry.breaker.new(...)`), и `nil`
из пары молча превратился бы там в «без размыкателя».

```lua
retry.breaker.new({ treshold = 0.1 })
--> app.lua:1: настройки размыкателя: ключа «treshold» нет, есть min_calls, name, probes, reset_timeout, retriable, threshold, window
retry.breaker.new({ window = 5 })
--> app.lua:1: настройки размыкателя: настройка min_calls больше window: окно не вместит столько исходов, и цепь не разомкнётся
```

В повторах размыкатель спрашивается перед каждой попыткой. Не пустил
первую — вызывающий получает отказ размыкателя; не пустил следующую —
отказ сервера из прошлой попытки: размыкатель лишь перестал ждать
от сервера другого ответа. Причина в `on_attempt` — `'breaker'`.

Без повторов вовсе — `breaker:call(action)`: действие получает тот же
аргумент, что и в цикле повторов, `{ attempt = 1, elapsed = 0 }`.
Для своих циклов есть `allow()` — пускает ли цепь вызов, с причиной
отказа — и `record(ok, err)` — запомнить исход. `reset()` замыкает цепь
и забывает окно. `status()` — что видно снаружи:

```lua
breaker:status()
--> { name = 'склад', state = 'open', calls = 0, failures = 0, threshold = 0.5,
--    min_calls = 2, probes_left = 0, silence_left = 29.9… }
```

Окно чистится на каждой смене состояния: исходы, собранные до
размыкания, описывают уже другую службу — ту, что лежала.

### Экземпляры: `new`, `configure`, `default`

Вызовы модуля — `retry.run`, `retry.policy`, `retry.reset`,
`retry.status` — идут через общий экземпляр процесса `retry.default()`.
Он заводится при первом обращении: загрузка модуля не заводит ни вёдер,
ни размыкателей.

`retry.configure(opts)` проверяет настройки и отвечает `true` либо
`false, err`; принятые ложатся в основу общего экземпляра, а собранный
по прежним забывается вместе с вёдрами — иначе новые настройки жили бы
со старыми вёдрами. Негодные настройки не принимаются, и остаются
прежние.

```lua
retry.configure({ attempts = 5, base = 0.2 })   --> true
retry.status().attempts                         --> 5
retry.configure({ attempts = 0 })
--> false, 'настройки повторов: настройка attempts — целое число от 1, а пришло: 0'
retry.status().attempts                         --> 5
```

`retry.new(opts)` заводит отдельный экземпляр — свои настройки, свои
вёдра — либо отвечает `nil, err`. У экземпляра те же `run`, `policy`,
`reset`, `status`, только через двоеточие.

```lua
local stock = retry.new({ attempts = 4, scope = 'склад' })

stock:run(action)
```

`status()` отдаёт настройки, `worst_case`, вёдра по именам (или `false`,
если бюджет выключен) и состояние размыкателя, если он задан.
Паролей и ключей там нет и не бывает: повторы их не видят.

```lua
retry.status()
--> { attempts = 5, base = 0.2, factor = 2, jitter = 1, max = 5, scope = 'default',
--    worst_case = 3, budget = {} }: ведро появится с первым вызовом

retry.run(action)
retry.status().budget
--> { default = { tokens = 100, max = 100, ratio = 0.1, allowed = true } }
```

### Журнал

Пакет пишет журналом `tnt-log` с именем `tnt.retry`:

| Уровень | Текст | Поля |
|---|---|---|
| `debug` | `повтор после отказа` | `attempt`, `delay`, `err` |
| `debug` | `повторов больше не будет` | `attempt`, `reason`, `elapsed` |
| `warn` | `on_attempt бросил и был пропущен` | `err` |
| `warn` | `retriable бросил; отказ считается постоянным` | `err` |
| `warn` | `размыкатель разомкнут` | `service`, `silence` |
| `info` | `размыкатель замкнут` | `service` |

### Подмена в проверках: `_set_source`

Часы, пауза и случай — внешние зависимости (`tnt-external`), и проверка
подменяет их, чтобы минутное ожидание не занимало минуту:

| Модуль | Что подменяется |
|---|---|
| `retry.runner` | `now` — монотонные часы, `scheduler_now` — время планировщика, `sleep` — пауза |
| `retry.breaker` | `now` — монотонные часы |
| `retry.backoff` | `random` — доля от 0 до 1, `urandom` — байты ядра для неё |

```lua
local now = 0
local slept = {}

retry.runner._set_source({
    now = function() return now end,
    scheduler_now = function() return now end,
    sleep = function(seconds)
        table.insert(slept, seconds)
        now = now + seconds
    end,
})
retry.backoff._set_source({ random = function() return 1 end })   -- полный разброс даёт расчётную паузу

retry.run(function() return nil, 'timeout' end, { attempts = 4 })
slept   --> { 0.1, 0.2, 0.4 }

retry.runner._set_source(nil)
retry.backoff._set_source(nil)
```

### Что умеет

| Вызов | Что делает |
|---|---|
| `retry.run(action, opts)` | выполняет действие с повторами через общий экземпляр; отказ — `nil, err` |
| `retry.policy(opts)` | собирает функцию повтора `call(action, extra)`; негодные настройки — `nil, err` |
| `retry.configure(opts)` | настраивает общий экземпляр; `true` либо `false, err` |
| `retry.default()` | общий экземпляр; заводится при первом обращении |
| `retry.new(opts)` | отдельный экземпляр со своими вёдрами; `nil, err` при негодных настройках |
| `retry.reset()`, `:reset()` | наливает вёдра заново |
| `retry.status()`, `:status()` | настройки, `worst_case`, вёдра, размыкатель |
| `retry.breaker.new(opts)` | размыкатель: `call`, `allow`, `record`, `state`, `status`, `reset`; негодные настройки — бросок |
| `retry.budget.new(opts)` | ведро: `allow`, `record`, `reset`, `status`; негодные настройки — бросок |
| `retry.budget.complaint(opts)` | текст отказа о настройках ведра либо `nil`, без броска |
| `retry.classify` | `verdict`, `of`, `strict`, `code_of`, `delay_of`, списки `permanent` и `transient` |
| `retry.backoff` | `raw`, `delay_for`, `fraction`, `DECORRELATED` |
| `retry.options` | `defaults`, `merge`, `check`, `resolve`, `worst_case` |
| `retry.runner` | `run`, `next_delay` и постоянные причин остановки |
| `retry.attempt` | `once`, `reason`, `NO_REASON` |

Части открыты тем, кто собирает своё поведение: свой цикл на `runner.run`
с готовыми настройками и своим ведром, свой судья поверх
`classify.verdict`, свой счёт пауз на `backoff.delay_for`.

## Чем пришлось поступиться

**Пакет не знает, можно ли повторять само действие.** «Отказ временный»
не значит «повторять безопасно»: перевод денег, оборвавшийся после того,
как сервер его принял, выглядит временным отказом и повторяется вторым
переводом. Неидемпотентное действие повторяют только под ключом
`tnt-once`, либо `retriable` говорит «нет» на всё, что могло дойти
до сервера.

**Неизвестный отказ повторяется.** Лишний повтор постоянного отказа
стоит двух обращений и записи в журнале — предел попыток и срок не дадут
ему стоить больше. Неповторённый временный отказ стоит отказа всей
работы, и стоит его молча. Кому лишнее обращение дорого — чужой сервер
со счётчиком запросов, действие с побочным следом, — тому
`retriable = retry.classify.strict`.

**Наружу проходит пара «значение и причина».** Действие, отвечающее
тремя значениями, третьего не досчитается — зато поведение одинаково
у всех, кто зовёт отсюда, и один договор об удаче у повторов
и размыкателя.

**Срок не обрывает идущую попытку.** Оборвать чужой вызов на середине
нельзя: у него свои сроки. Действие, которое не сложило `context.left`
в свой таймаут, может кончиться позже срока вызова.

**Код ответа — только из полей, `Retry-After` — только секунды.**
Три цифры в тексте не говорят, чей это протокол, а дата меряется
чужими часами. Отказ без полей судится словами.

**Ведро и размыкатель живут в процессе.** Каждый узел считает отказы
и размыкает цепь сам, на своих наблюдениях; общего мнения кластера
о здоровье службы здесь нет. Ведро считает с той минуты, как его завели:
вчерашняя авария держит его полупустым, пока удачные вызовы не нальют
жетоны обратно, и читать его как «состояние службы сейчас» нельзя —
для этого есть окно размыкателя.

**Списки слов общие на процесс.** `classify.permanent`
и `classify.transient` — массивы модуля, и слово, дописанное одним
клиентом, видят все. Своё суждение, которое не должно касаться соседей,
задаётся настройкой `retriable`.

**Политика помнит свой экземпляр.** `retry.policy` собирает функцию
на общем экземпляре того мига. `configure` после этого заводит новый
экземпляр, а собранная раньше политика остаётся на прежнем — с прежними
настройками под своими и с прежними вёдрами. Политики собираются после
`configure`.

**Размыкатель решает по одной пробе.** Первая удачная проба замыкает
цепь, и требовать нескольких удач подряд незачем: служба, которая
не встала, отсеется окном, считающим долю отказов с первой минуты после
замыкания. `probes` поэтому говорит не «сколько удач ждём», а «сколько
вызовов пускаем, пока проверяем».

**Случай — из байтов ядра, не из `math.random`.** Пауза стоит чтения
четырёх байтов `digest.urandom` — около 1,8 мкс на 3.8 против сотой
доли микросекунды у `math.random`, — и платит их повтор, который
и так ждёт десятые доли секунды. Зато разброс разбрасывает и между
узлами, а общий на процесс генератор никто не пересевает.

## Проверки

Проверки лежат в `test/` и идут на luatest: `.rocks/bin/luatest test/`.
Модули пакета берутся из исходников, зависимости — установленными.

Часы, пауза и случай подменены: время двигает сама пауза, отметка
цикла событий отстаёт на заданную работу без уступки, случай — число,
выбранное проверкой, и паузы сверяются точной арифметикой. Отдельно
проверено, что доля по умолчанию складывается из четырёх байтов ядра
и что две настоящие доли подряд различаются. Журнал ловится ловушкой:
броски `retriable` и `on_attempt` видны только записью. Отказы настроек
сверяются текстом целиком — вместе с приставкой, чтобы вторая такая же
впереди не прошла незамеченной, — а броски ведра и размыкателя сверяются
вместе с местом: оно обязано указывать на строку того, кто их заводит.
Размыкатель проходит все три состояния на часах, которые двигает
проверка.

Покрытие строк — 100 %, убитых мутантов — 100 % (159 проверок,
545 мутантов в девяти модулях).
